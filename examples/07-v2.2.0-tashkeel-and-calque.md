# Example 07: v2.2.0 — Tashkeel reduction + pipeline-calque substitution

This example demonstrates the two new transformations added in v2.2.0:

1. **English-calque → native Arabic** — `خط أنابيب` (literal "line of pipes", the calque of English "pipeline") becomes `مسار العمل` (workflow / path-of-work)
2. **Tashkeel reduction** — heavy diacritics are stripped in `news` register per modern editorial convention. Hamza letter forms (`أ`, `إ`, `آ`) and Arabic digits (`٠-٩`) are PRESERVED — they're distinct letters that carry meaning, not diacritics.

## Reproduction command

```bash
python scripts/humanize_v2.py \
  --input examples/07-v2.2.0-tashkeel-and-calque.input.txt \
  --mode tighten --register news \
  --output examples/07-v2.2.0-tashkeel-and-calque.output.txt
```

No API key needed — `tighten` mode is fully deterministic.

## Input (AI-generated Arabic, heavy tashkeel + pipeline calque)

```
خَطُّ أنابيب المُعالَجَة يَستخدمُ نَموذجاً لُغَوياً مُتَقَدِّماً. علاوة على ذلك، فإنَّ النَّتائِجَ تُظهِرُ تَحَسُّناً مَلحوظاً. في الواقع، يَعتمدُ النِّظامُ على إن النصَّ المُولَّدَ يَخضعُ لِأربعِ مَراحلَ تَحويليَّةٍ مُتَتاليَةٍ.
```

The input has **two AI signatures**:
- The calque `خَطُّ أنابيب` (a literal-translation artifact — English "pipeline" rendered as "line of pipes")
- ~30 tashkeel marks across the prose (over-decorated; humans rarely tashkeel like this outside Qur'anic / poetic contexts)

## Output (after v2.2.0 lex pass with `--register news`)

```
مسار العمل المعالجة يستخدم نموذجا لغويا متقدما. وفوق ذلك، فإن النتائج تظهر تحسنا ملحوظا. يعتمد النظام على إن النص المولد يخضع لأربع مراحل تحويلية متتالية.
```

## What changed and why

| Transformation | Example | Pass |
|---|---|---|
| Calque → workflow | `خَطُّ أنابيب` → `مسار العمل` | `AI_PHRASES_AR` (v2.2.0) |
| Tashkeel stripped | `المُعالَجَة` → `المعالجة` | `lex_reduce_tashkeel` (v2.2.0) |
| Tashkeel stripped | `يَستخدمُ نَموذجاً` → `يستخدم نموذجا` | `lex_reduce_tashkeel` |
| Hamza letter PRESERVED | `إن` stays `إن` (NOT `ان` or `أن`) | hamza-safe regex |
| Hamza letter PRESERVED | `أربع` stays `أربع` | hamza-safe regex |
| Connector swap | `علاوة على ذلك،` → `وفوق ذلك،` | `lex_replace_connectors` (existing) |
| Fluff deletion | `في الواقع،` → *(deleted)* | `lex_replace_phrases` (existing) |

The skill correctly:
- ✅ Replaces the English calque with native Arabic
- ✅ Strips non-disambiguating tashkeel
- ✅ Preserves hamza distinctions (`إن` vs `أن` are different words — both meaning would have been lost if hamza letters were stripped)
- ✅ Preserves Arabic-Indic digits (none in this input, but the same regex protects them — see fragility test T9)

## What `--register classical` would do differently

```bash
python scripts/humanize_v2.py \
  --input examples/07-v2.2.0-tashkeel-and-calque.input.txt \
  --mode tighten --register classical \
  --output /tmp/classical-output.txt
```

In `classical` register, tashkeel is preserved per traditional Arabic editorial convention. The calque substitution still runs (it's a lexical fix, not a stylistic one), but the surviving prose keeps its diacritics. The same `--register technical` would also preserve tashkeel (conservative-by-design).

## Reproducibility

This output is **byte-deterministic**. The lex pass uses no random state; register gates fire deterministically. Running this command on any machine with v2.2.0+ produces this exact output.
